# Chat Portraits and Message Labels

Evidence report, log, and screenshot paths under `../tmp/` below refer to local private acceptance artifacts. They are not distributed with the public repository.

Click "Chat portrait" in the chat toolbar to replace the right-hand chat area with the portrait dashboard while keeping the conversation list on the left. "Return to chat" restores the chat, unsent draft, and attachments; clicking an original source also returns to the chat and locates it. Under "Analysis target and start", select the whole group or a specific member, then start. Members cannot be changed during submission or execution, but can be changed after cancellation. Analysis settings, time scope, model management, history, and saved-label visibility are grouped under "Analysis settings and history". The default is "Local Laya · statistical portrait"; API mode must be selected manually. The default scope is the latest seven days, excluding the end time. Opening portraits, viewing history, and showing saved labels do not start a model. Automatic message recognition is controlled by "Intent recognition" next to "Images/files" in the input area and shares the portrait's analysis mode.

The dashboard shows actual coverage, person information, closeness tendency, four MBTI axes, an interaction radar, common topics, and a summary, while retaining evidence and uncertainty. Whole-group analysis uses the same card layout, replacing personal MBTI with group atmosphere. "Speaker count" means people who actually spoke within the selected scope, not total group membership. Closeness tendency displays existing scores without inferring additional relationship levels; unknown scores are not filled with zero.

Before first use of local mode, click "Download model" or expand "Import existing model directory" and select a complete directory. Downloads show progress and can be paused and explicitly continued. The model totals 681,238,131 bytes (approximately 681 MB); installers do not include weights. Each file's size and SHA-256 are checked against a pinned revision, and readiness is shown only after all checks pass. Download failure does not automatically change sources, retry, or call an API. Import validates and copies files into the application model directory without changing the original directory.

Laya is a classification and scoring model. Message labels use fine-grained candidates; portraits retain broad emotion/intent categories, six-dimensional statistics, relationship signals, common wording, and short statistical summaries rather than freely generating long explanations. It explicitly uses CPU (4 threads); inference with a ready model is offline and requires no API Key. Select API mode for detailed textual analysis. Histories and message labels from the two sources are shown separately, and existing API history remains available.

Private chats provide a person summary, topics, communication characteristics, a six-dimensional interaction radar, emotions, interaction closeness tendency, and chat-based MBTI speculation. Groups can analyze the whole group or load members who have spoken on demand and select one. Whole groups have neither affinity nor MBTI scores; group members do not have private-chat affinity scores. Members are distinguished by WeChat ID, without merging identical display names.

New private-chat portrait tasks filter by the other person's WeChat ID at the message-read entry point. Local and API modes save, count, and analyze only that person's messages; the user's own messages do not enter the task. Selecting a group member likewise processes only that member; whole-group analysis still processes everyone. Adjacent context includes only the target's preceding three valid text messages at most. Read counts include the target's non-text messages such as images, while analysis progress counts valid text only. Tasks save `read_scope` and `analysis_scope` (`peer` for private chats, `member` for group members, `conversation` for whole groups); the UI explains counts separately by read and analysis scope. Old private-chat tasks analyzed both participants. Old member tasks without `read_scope` still show whole-conversation read coverage; earlier member tasks without `analysis_scope` also analyzed whole-conversation text. Historical results and counts are retained with their original scope indicated. Use "Analyze again (new task)" for processing under the new scope.

Automatic intent recognition in the chat window queues only loaded text from the other private-chat participant or other group members. Initial opening, history scrolling, new messages, and adjacent preceding context all exclude the user's own messages. The backend checks sender ownership against actual message sources. A batch or preceding context containing the user's messages explicitly fails without a model call. Historical labels on all of the user's own bubbles are no longer restored or shown, including old manual-portrait labels; stored records remain. Other people's saved labels are reused without duplicate recognition on upgrade. Group atmosphere first excludes the user, then counts the latest 20 recognized messages from other members. Snapshots use the user's identity from account metadata, while live accounts reuse the native WeChat ID to avoid confusion with suffixed directory names. Quoted text carried within a message remains context only and does not produce labels for the quoted speaker.

MBTI becomes available only after at least 100 valid text messages from the target person have been analyzed; each dimension may still show "Insufficient evidence". The 100-message threshold is only a display gate, not evidence of reliability or psychometric validity. All scores are model estimates of the selected text, not probabilities, actual feelings, or psychological diagnoses.

Portrait history supports removing individual entries or clearing by current account, chat, group member, and analysis mode. Clearing sets only `history_hidden`, retaining tasks, portraits, message labels, original evidence, and the saved portraits/caches used by automatic recognition. Queued or running tasks cannot be removed individually; bulk clearing skips them. Clearing does not change result chronology. Reopening can still restore the latest result for the current target/model, and retained results remain accessible.

New manual-portrait tasks reuse saved labels matching current settings by default, including valid portions of failed or cancelled tasks; completed messages need no repeated recognition. "Recompute all messages from scratch" disables reuse for this request only, without modifying old tasks. Progress distinguishes reused and newly recognized counts. Scanning still reads the currently selected scope; reused messages enter adjacent context and the final portrait. API final portraits still reorganize the complete material, so skipping label recognition does not make the entire task call-free.

Reuse occurs only between manual tasks, checking account, conversation, analysis target, read scope, data source, model configuration/version, and message identity, time, sender, original text, and quotation content. Originals cited by labels must also exist unchanged in the current material. Running tasks are not reuse sources; hiding history entries preserves usable results. Local Laya additionally requires the corresponding statistical results and classification rules. New tasks record the source task for reused labels, without copying old cost records as new calls. Reuse retains the historical judgment from that time and is not fresh inference with new context; use recomputation when existing labels need reevaluation.

## Message Label Style and Current Scope

Message labels use the original project's compact text row, for example "Emotion Happy  Intent Sharing": pale field names, normal text color for results, no filled badge, colon, or separate "Evidence" button. Laya and API use the same component. Hovering or clicking a label row reveals original analysis evidence; keyboard focus and expansion are supported.

| Capability described by the original project | Current project status |
| --- | --- |
| One emotion and one intent per message; restore existing labels after turning recognition off | Supported; automatic switches/caches persist by account, conversation, and model source, while manual-label visibility remains separately controlled |
| Local fine categories such as anticipation, probing, or polite refusal | Dynamic candidate classification is integrated; wording retrieves candidates only, final labels come from the model, and low confidence remains unknown |
| Every label is at most four Chinese characters | Local candidates and API schema strictly enforce four characters maximum; longer results raise errors |
| Recognize messages using recent chats and saved portraits | Recent chats, quotations, and sender portraits matching account/conversation/model source inform judgment; portraits are weak references and cannot replace current originals |
| Automatic analysis when opening a conversation, scrolling history, or receiving new messages | With intent recognition enabled, loaded messages are processed serially in batches; new messages/history pages join the queue; disabled by default |
| Results appear progressively during analysis | Laya saves each completed message; each complete API-stream label is saved immediately after validation; closure, missing fields, or disconnection does not erase prior results |
| Punctuation-only analysis | Nonempty punctuation text can participate; results still depend on the model |
| Person emotion or group atmosphere at the top of chat | Private chats show emotion from the latest analyzed messages of the other person; groups show statistical atmosphere from the latest 20 analyzed messages of other members, excluding the user |

The same Laya weights can serve different classification flows; adopting the model does not automatically provide scheduling or display features. Manual labels and statistical portraits separately save raw fine-category and broad-category outputs so their evidence can be traced.

## Automatic Intent Recognition

Enabling "Intent recognition" on the chat page analyzes loaded text with the selected API or Laya mode. API mode sends these originals and may incur call costs; Laya requires a complete model first. Turning the switch off stops the active batch for this scope and hides automatic labels, which restore from storage on reenabling. Enabled scopes retain the choice on reentry. Failed or application-exit-interrupted batches require an explicit retry and do not automatically incur new charges.

Each batch contains at most 20 target messages and 3 adjacent preceding messages. Concurrently arriving history/new messages remain queued after the active batch. Caches match account, conversation, model source, message identity, and original-text fingerprints, without another call on a hit. After switching conversations, submitted old batches finish in their original scope; old messages are not submitted to the new conversation. Automatic batches are stored independently rather than putting every page into manual "Analysis history".

The top-of-chat state reflects only analyzed material. Private chats use the latest message of the other person; groups exclude the user, then take the latest 20 messages of other members, independently of the portrait panel's member filter. A group emotion appears only if it covers at least half the sample and leads uniquely; otherwise the result is explicitly unclear. Unknown messages still count in the sample. History scrolling does not replace newer emotion state with older state. These statistics are not psychological conclusions about all group members.

Saved portraits use only the latest person summary, communication characteristics, and uncertainty matching account, conversation, model source, and sender. A whole-group portrait is not treated as a member portrait. Old portraits are weak references, and current originals take priority. API and Laya retain all selected reference fields instead of truncating or silently dropping portraits to bypass capacity limits.

## Originals and Scope

Only nonempty text and the sender's own written portion of quoted replies are analyzed. Quoted speech is separate context, not the sender's own expression. Images, audio/video, and files contribute only skipped counts. Tasks save exact scope, model, data source, coverage, and conclusion sources; clicking a source locates the original message. Changed message content no longer shows its old labels.

Live accounts must connect to the live message source or the task fails; imported accounts explicitly use their imported snapshot. Old snapshots cannot silently stand in for current chats. Large chat scopes first paginate and save the current material. API mode generates labels in batches according to model input/output capacity, producing a compressed portrait with sources before cumulative material reaches the budget threshold, then reading further and organizing the final portrait. Adjacent messages from the previous window provide context; earlier portraits carry only generated conclusions and a directory of source identities. Complete originals remain local for review instead of resending the whole history every round.

Local mode saves fine labels and updates the cumulative statistical portrait of analyzed target text after every classified message; portraits completed before a failure remain viewable. At most three adjacent messages and quotation text provide context; fine labels also read saved portraits matching identity and model source. Portraits are supplied as complete weak references; they cannot override current speech or serve as evidence for new facts. Laya has a fixed 1024-token input limit, including question, options, text, context, and portrait. Overflow raises an explicit error without truncating text or silently omitting the portrait. The API's 258k budget and compaction policy do not apply to Laya.

## Provenance and Verification Boundaries

Feature and display dimensions reference [WechatVibe 78446c0](https://github.com/tswawa/WechatVibe/tree/78446c00dc0d0e014a5a51f86ab000d5848051fe). API analysis services, prompts, and Vue UI were written independently. Local questions and relationship weights reference that project; ONNX input construction and temperature calibration were ported from [Laya-MLX dc3aa6b](https://github.com/mizchi/laya-mlx/tree/dc3aa6b150cb861d0788fbd421cfd1303de4ed57), using the [pinned multilingual ONNX model](https://huggingface.co/mizchi/laya-multilingual-onnx/tree/d9d003d543e63d6d3375c21d44624136bd1e0bad). Source and model both declare Apache-2.0; complete licenses and change notices remain in resources/licenses. WeChat readers, the Node desktop runtime, and demo avatars were not copied.

Local statistical-rule version `laya-statistics-v1`: labels display only when the highest category probability reaches 50%; otherwise evidence is explicitly insufficient. Six dimensions use the mean of positive signals in target speech. Closeness tendency uses only the other person's relationship distribution and time weights; empty evidence is not filled with 50. Common wording uses jieba segmentation counts. MBTI additionally requires the model to identify self-reported stable preferences, and axes dominated by unknown are not scored. The user explicitly selected statistical-rule wording; it is not fixed text impersonating model success.

Fine-label-rule version `laya-fine-v1-generic-v9`: candidate retrieval follows the generic-v9 flow of pinned WechatVibe `electron/laya/general-intent.ts`, with some added short candidates. Emotion and intent are both chosen by the model. Candidates include anticipation, feeling wronged, tiredness, probing, polite refusal, and perfunctory response; results may still be inaccurate or fall below the display threshold. Raw candidates, answers, and versions are saved with messages. Keywords do not override model answers, and model failure does not generate default labels.

Unit and endpoint tests use isolated storage and authored samples. `tools/verify_chat_insights_model.py` calls the actually selected model with authored private-chat, group-chat, and same-name-member samples. It loads model configuration read-only, without reading private chats or copying keys to test storage. It records structure/source checks, duration, and token usage; a few successful samples do not establish general accuracy.
