# 第四轮：统一检索与质量优化

**目标：** 按用户新顺序先完成第四轮，再进行第二轮和第三轮。提供同一入口搜索当前账号的聊天、附件提取正文、OCR 文字及当前资料正文/笔记，明确出处、覆盖与错误，并依据实测优化。

**后续入口整合（2026-10-13）：** 按用户要求，统一搜索与附件中心已合并为侧栏“搜索”内的“全部内容／附件”视图，共用账号、关键词和日期；保留全部附件操作，旧附件地址重定向。完整使用与验收说明见[搜索：内容与附件](../../unified-search.md)。

**设计：** 复用消息 SQLite 索引、AIStore 附件提取缓存与资料记录。入口默认本地关键词，空格分词 AND，最多 8 词，超限明确拒绝；不调用模型、自动 OCR 或新增向量/索引依赖。按四个来源分组，各组独立请求、分页与错误状态。

## 范围及接口

- 新侧栏入口 `/search`，使用 `applicationAccounts`；只有资料副本的账号仍可搜索资料。源库缺失显示来源不可用，不能当作零命中。
- `GET /api/search?account=...&q=...&source=chat|documents|ocr|notes&offset=0&limit=20`；可选 `start_time/end_time`，聊天/附件按消息时间，资料按更新时间。所有筛选在分页前执行。
- 返回 `account/query/source/status/items/has_more/next_offset/coverage/elapsed_ms`。`status` 区分 `ready/unavailable/index_building/index_error`；读写/损坏等错误通过明确 HTTP 错误，由界面保留来源归属，不返回成功空结果。
- 结果字段：`id/source/title/snippet/matched_fields/timestamp`；消息及附件提供 `username/anchor/conversation_name/sender/sender_name`，资料提供 `library_item_id/folder_id/folder_name/item_kind`；OCR/附件提供 `extraction` 元数据。使用普通文本呈现摘录，不注入 HTML。
- `coverage` 给出可核实的 `available/searched/message` 与索引新鲜度；附件补充未提取、失效、空文本、部分结果与提取方法数量，未知数量返回 null 而非零。覆盖统计不受关键词命中数影响。
- 聊天读取现有 `message_fts/message_meta` 的索引正文和来源，不走旧查询结果补全中吞异常的分支。复用候选构建、分词、字面复核和摘录函数，复核在 LIMIT/OFFSET 前执行。仅符号类查询显式使用字面扫描并记录执行方式；不是捕获异常后降级。
- 附件正文/OCR 按实际提取方法分组，复用来源签名校验；过期缓存不作为当前结果，部分提取必须标明。普通文档字层不等于图片 OCR 已覆盖。
- 资料搜索当前 `library_item` 的 title/content/notes/tags，包含保存的报告及文字副本。历史专题版本不加入本轮结果，覆盖文案明确说明，避免历史快照重复淹没当前材料。
- 查询词不放进 URL 导航地址、浏览器持久化或新增调试日志。账号/条件改变取消旧请求，恢复资料后旧结果失效并提示重新查询。

## 实施与验证

- [x] 后端搜索及测试：复用索引/缓存，字面匹配一致性、账号隔离、仅资料账号、过滤与分页、损坏/失效缓存、索引新鲜度。
- [x] 前端搜索页与导航：来源分组、覆盖、独立错误和续页，隐私模式，资料定位和原消息跳转，取消及旧响应保护。
- [x] 固定语料验收：四源正负例、多词、中文/大小写/编号金额/符号、缺失与过期材料；核对命中身份、字段和翻页。
- [x] 性能基准：104 场景完整矩阵、每源 p50/p95、耗时和响应大小；最终串行复测聊天首页约 59.92 → 20.47 ms、资料日期范围约 65.99 → 27.48 ms；附件无明确提速。
- [x] 相关回归、生产构建、生产页面加真实 HTTP 受控数据验收、独立审查；[完整说明、实测与验收边界](../../unified-search.md)。

## 约束

- 保留第一轮备份/恢复及工作区其余修改，不发布或覆盖用户数据。
- 不把基础索引里的片段当成最新源库已核对的原文；点击原消息继续走既有来源定位。
- 不新增隐式降级、查询失败后切模式、自动重试或假成功。
- 不先增加缓存/索引再宣称加速；先测量并记录瓶颈。
