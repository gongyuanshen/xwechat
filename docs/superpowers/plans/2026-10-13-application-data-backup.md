# 第一轮：应用资料备份与隔离恢复实施计划

> 此文件是最初隔离恢复实现的历史记录。用户指出隔离副本不能作为最终恢复结果后，已要求补齐写回正式资料库。当前产品范围以 [正式恢复补齐计划](2026-10-13-application-data-live-restore.md) 和 [使用说明](../../application-data-backup.md) 为准；下方“仅隔离恢复”边界已被取代。

**目标：** 按用户给定的四轮顺序，先交付可下载的应用资料备份、隔离恢复和可核查结果，再进入专题 Agent 联动、持续跟进与统一检索。

**设计依据：** 本轮按用户已授权的第一轮范围实施。应用资料位于共享 AIStore，与微信账号归档分开。复用现有记录、附件引用、账号工作租约和 ZIP 校验基础设施，不增加依赖；保留工作区已有事项与专题修改。

## 范围与接口

- 单账号白名单：`matter`、`library_folder`、`library_item`、`library_version`、`library_search`。笔记、报告原始回答及引用、OCR 文字副本均保留在原记录中。保留事项关联的未投递提醒，避免事项状态与提醒队列脱节。
- 附件取当前资料及全部历史版本引用的并集，按 ID 去重；核对元数据大小及 SHA-256。不能仅打包当前资料。
- 不复制整个 AI 数据库：其中还有模型凭据、任务及其他账号数据。聊天数据库仍使用原账号归档。
- `POST /api/data-backup/export?account=...`：一次生成 ZIP 并下载。文件名不含账号名。
- `POST /api/data-backup/restore`：上传 multipart `file`，无需当前账号；恢复到输出目录的 `application_restores/<uuid>/ai`，不写入运行中的 AIStore，不触发提醒或模型。
- 恢复返回 `status=verified`、`account`、`restore_path`、`counts`、`attachment_bytes`、`content_sha256`，并落盘 `verification.json`。counts 含 `matters/folders/items/versions/searches/notes/reports/attachments/pending_reminders`；notes/reports 统计当前资料，历史内容由 versions 覆盖。
- 隔离副本可由现有资料/事项服务读取；本轮没有覆盖或合并当前账号的操作。此边界在设置入口、结果及文档明示。

- [x] 设置入口：`ApplicationBackupSettings.vue` 与 `SettingsDialog.vue`，账号选择、下载、ZIP 上传恢复、统计和路径；保持隐私遮挡、请求身份、错误展示、禁止自动重试。
- [x] 集成验收：相关后端/前端回归、Nuxt 构建、独立审查；在隔离目录使用真实服务读取恢复数据和核对附件。记录实测范围，区分受控数据与真实账号/桌面安装包验收。

## 重点检查

1. 当前资料已删除但专题历史仍引用的附件不能漏备份。
2. 导出期间的资料删除不能导致 ZIP 内容与记录快照不一致。
3. 未投递事项提醒必须与事项状态一起保存，隔离恢复不启动投递。
4. 恶意 ZIP 路径、额外文件、跨账号记录、坏引用及内容摘要不符在入口失败。
5. 上传、下载异常及账号切换不显示伪造成功，不自动重试；恢复不能覆盖现有资料。
